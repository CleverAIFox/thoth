## 1. 무엇인가

영어로 된 학습 사이트의 문항·본문을 **사용자 브라우저에 이미 렌더된 상태에서
읽어** 한글 번역을 겹쳐 보여주는 크롬 확장과, 번역을 수행하는 백엔드다.

이름은 문자·언어·중재의 신 토트에서 왔다. 그리스에서 헤르메스와 동일시되었고,
`hermēneus`(통역자)가 그 계통의 말이다.

### 1-1. 구조

```
[브라우저]
  어댑터   사이트별 DOM 지식. 번역 대상(Unit)을 모은다
  브로커   어댑터 선택 · 자리 선점 · 배치 · 삽입. 사이트를 모른다
  클라이언트  워커 호출
        │
        ▼ POST /translate  (+ X-Thoth-Token)
[워커]
  계약     검증 · 토큰 · 응답 형태. 프레임워크를 모른다
  캐시     sha256(원문) → 번역. 미스만 다음 단계로
  가드     월 누적 문자 상한. 번역 전에 예약한다
  용어집   원문에 맞는 도메인 용어집을 골라 프롬프트에 싣는다
  엔진     echo · local · translate · bedrock
```

**사이트 지식은 어댑터에만 있다.** 브로커·클라이언트·워커는 어떤 사이트인지
모른다. 새 사이트 대응은 어댑터 파일 추가로 끝난다.

### 1-2. 어디서 도는가

| | 입구 | 엔진 · 저장소 |
|---|---|---|
| 로컬 | `uvicorn` → `app/main.py` | `local`(ollama) · 파일 |
| 배포 | Function URL → `app/lambda_handler.py` | `bedrock` · DynamoDB |

**두 입구가 같은 `contract.py` 를 부른다.** 같은 입력에 같은 상태 코드 · 같은
에러 이름 · 같은 응답 바이트가 나오고, 검사가 그것을 대조한다(DECISIONS §68 ·
§71 · §76).

★ **ASGI 어댑터를 쓰지 않는다.** Mangum 을 끼우면 Lambda 패키지에 FastAPI 와
pydantic 이 들어간다. 계약을 떼는 쪽이 중복도 0 이고 배포 패키지가 **18KB** 다.

★ 배포본은 2026-09-14 에 섰고 Udemy 실사이트에서 확인했다. 문항 하나에 **5.2초**
(로컬 엔진 80.7초), 45유닛 골든셋 위반 2건이다.

## 2. 어댑터 계약

### 2-1. Unit

번역 대상 하나를 나타내는 유일한 추상이다.

| 필드 | 뜻 |
|---|---|
| `id` | 이번 수집 안에서만 유효한 식별자 |
| `text` | 원문 |
| `el` | 텍스트를 읽은 노드. `dataset.stDone` 으로 중복 수집을 막는다 |
| `anchor` | 번역을 꽂을 위치. `el` 과 다를 수 있다 |
| `group` | 같은 값끼리 한 배치로 번역된다. `null` 이면 단독 |

★ `el` 과 `anchor` 를 나눈 것이 핵심이다. 텍스트를 읽는 노드가 좁은 grid 칸
안에 있으면 거기에 번역을 꽂았을 때 글자가 세로로 쪼개진다. 삽입은 한 단계
넓은 조상에 한다.

### 2-2. 인터페이스

| 함수 | 필수 | 역할 |
|---|---|---|
| `match(location)` | ○ | 이 페이지를 맡을지 |
| `collect(root)` | ○ | Unit 배열을 돌려준다 |
| `anchorFor(el)` | — | 삽입 위치. 기본값은 `el` |
| `decorate(node, unit)` | — | 레이아웃 보정. 기본값은 무동작 |

### 2-3. 계층

`priority` 내림차순으로 정렬해 `match()` 가 참인 첫 어댑터를 쓴다.

| 계층 | 어댑터 | priority | 사이트 지식 |
|---|---|---|---|
| 2 | `udemy` | 10 | 있음 |
| 1 | `standard` | 5 | 없음. ARIA · 폼 표준 |
| 0 | `generic` | 0 | 없음. `match` 가 항상 참 |

★ **Layer 0 이 항상 참이므로 어댑터가 없는 사이트에서도 번역이 동작한다.**
어댑터는 동작 조건이 아니라 그룹핑과 레이아웃 정확도를 높이는 장치다.

★ **선택은 배타적이다. 이긴 어댑터 하나만 돈다.** 따라서 상위 계층은 하위
계층의 상위집합이어야 한다. `standard` 는 자기 몫을 모은 뒤 나머지를
`ST.genericCollect(root, {skip})` 로 Layer 0 에 위임한다. 이 규칙을 어기면
상위 계층이 걸린 페이지에서 본문이 통째로 빠진다(DECISIONS §11).

★ **`match` 는 능력의 선언이다.** "이 페이지에 아는 것이 있는가" 가 아니라
"하위 계층보다 낫게 다룰 수 있는가" 를 물어야 한다. 전자로 적으면 관심만 있고
능력은 없는 경우에 이겨 버린다 — `standard` 의 `match` 가 네이티브 라디오를
보는데 `collect` 는 ARIA role 만 순회해, 그런 폼에서 이기고도 그룹을 만들지
못했다(DECISIONS §39).

★ `standard` 가 묶는 것은 둘이다. `[role=radiogroup]` · `[role=listbox]` 안의
보기와, **같은 `name` 을 가진 네이티브 라디오의 라벨**이다. 후자가 표준인
이유는 HTML 명세가 그렇게 정하기 때문이며 사이트 지식이 아니다. 라디오가
하나뿐인 `name` 은 묶을 것이 없으므로 그룹으로 만들지 않는다.

## 3. Udemy DOM 계약

2026-09-12 실측이다. 채점 전후로 DOM 이 다르다.

| 대상 | 채점 전 | 채점 후 |
|---|---|---|
| 스코프 | `.quiz-page-content` | 동일 |
| 문제 | `#question-prompt` | 동일 |
| 보기 | `.ud-unstyled-list` 내 `div[data-purpose='safely-set-inner-html:rich-text-viewer:html']` | `#answer-text` × 4 |
| 해설 | 없음 | `#question-explanation` × 4 |
| 앵커 | `[class*=answer-inner]` | `[data-purpose=answer-body]` |
| rich-text 노드 수 | 5 | 9 |

### 3-1. 주의

★ **`#answer-text` 와 `#question-explanation` 은 같은 id 가 4번씩 쓰인다.**
HTML 위반이지만 Udemy 가 그렇게 한다. `getElementById` 는 첫 개만 잡으므로
`querySelectorAll('[id=...]')` 을 쓴다.

★ **채점 후 순서가 문제 · 보기1 · 해설1 · 보기2 · 해설2 … 로 섞인다.**
수집을 인덱스로 자르면 채점 후에 전부 밀린다(DECISIONS §1).

★ 보기와 해설은 같은 `result-pane` 안에 형제로 들어간다. 짝을 지으려면 이
컨테이너를 기준으로 한다.

★ **해시가 붙은 클래스(`--Sw1to` 등)는 빌드마다 바뀐다.**
`.quiz-page-content` 와 `.ud-unstyled-list` 는 해시가 없어 안전하다.
`answer-inner` 는 `[class*=...]` 부분 일치로 잡는다.

## 4. 워커 계약

**계약은 `app/contract.py` 에 있고 프레임워크를 모른다.** `app/main.py` 는
FastAPI 배선만 들고, 배포본의 Lambda 핸들러도 같은 함수를 부른다.

| 파일 | 아는 것 |
|---|---|
| `contract.py` | 검증 · 토큰 · 캐시/가드/엔진 호출 · 응답 형태 |
| `main.py` | 로컬. 미들웨어 · 경로 · `JSONResponse` |
| `lambda_handler.py` | 배포본. Function URL 이벤트의 모양 |

★ **ASGI 어댑터를 쓰지 않는다.** Mangum 을 끼우면 Lambda 패키지에 FastAPI 와
pydantic 이 들어가고 콜드스타트가 1초 넘게 붙는다. 첫 문항 5.2초에 얹히는
시간이라 사용자가 체감한다(DECISIONS §68).

★ **두 경로의 응답 바이트가 같다.** 파싱 결과만 맞추면 `{"a": 1}` 과 `{"a":1}`
이 갈리고, 문자열로 보는 검사가 한쪽에서만 통과한다. Lambda 도 FastAPI 와 같은
구분자로 직렬화한다(DECISIONS §76).

★ **잘못된 본문은 400 이다.** `smoke.sh` 가 빈 배열 · `texts` 누락 · 문자열
아님 셋을 실제 HTTP 로 확인한다.

★ **본문 검증을 pydantic 에 맡기지 않는다.** 맡기면 잘못된 본문이 로컬에서는
422, 배포본에서는 다른 코드가 되어 **같은 입력에 두 답**이 나온다. `validate`
하나가 모양과 내용을 함께 본다. 잘못된 본문은 어느 경로에서나 400 이다.

★ **두 경로가 같은 답을 내는지 검사가 본다.** 같은 입력을 직접 호출과 HTTP 로
넣고 상태 코드와 에러 이름을 대조한다. 떼어 놓고 대조하지 않으면 떼어 놓은
의미가 없다.


```
POST /translate
req : { "texts": ["...", "..."], "target": "ko",
        "source": { "site": "호스트", "adapter": "이름" } }   texts 는 1~50개 · source 는 선택
hdr : X-Thoth-Token: <값>                              WORKER_TOKEN 이 설정된 경우만
res : { "translations": [...], "cached": [bool, ...], "version": "0.1.0" }

400 : { "error": "unsupported_target", "detail": "..." }   target 이 ko 가 아니다
400 : { "error": "bad_request", "detail": "source_..." }  source 모양이 틀렸다
401 : { "error": "unauthorized" }      토큰 불일치 (§12)
429 : { "error": "quota_exceeded" }    월 문자 상한 초과
413 : { "error": "too_long" }          단일 텍스트가 상한 초과
502 : { "error": "engine_failed", "detail": "..." }
503 : { "error": "guard_unavailable", "detail": "..." }    카운터 저장소 불통
```

### 4-0. 부분 응답

가드 실패(429 · 413 · 503)에서 **캐시 히트가 하나라도 있으면 200 으로 내린다.**

```
res : { "translations": ["번역", null], "cached": [true, false],
        "version": "0.1.0", "partial": "quota_exceeded" }
```

★ **캐시 히트는 과금이 0 이므로 상한과 관계가 없다.** 가드가 지키는 것은
요청이 아니라 번역 호출이다. 관계없는 것을 같은 판정에 묶으면 보여줄 수
있는 것까지 감춘다(DECISIONS §24).

★ 히트가 하나도 없으면 종전대로 상태 코드로 끝난다. 돌려줄 것이 없는데
200 을 쓰지 않는다.

★ **엔진 실패(502)는 부분 응답을 타지 않는다.** 가드 실패는 재시도로 풀리지
않지만 엔진 실패는 일시적이다. 200 으로 내리면 확장이 재시도 근거를 잃고 그
자리를 영구 실패로 버린다.

★ `partial` 이 실린 응답을 받으면 브로커가 순회를 멈춘다. 사유가 영구적인데
멈추지 않으면 캐시 히트만 계속 받으면서 워커를 때린다(DECISIONS §12).

★ `partial` 키는 부분 응답에만 있다. 전량이 채워진 응답에는 없다.

★ **4xx 는 같은 입력으로 재시도해도 결과가 같다.** 확장이 이 경계로 영구
실패와 일시 실패를 가른다. 5xx 와 네트워크 오류만 재시도한다(DECISIONS §12).

★ **503 은 열지 않고 닫는 선택이다.** 카운터를 세지 못하는 상태로 번역하면
상한이 없는 것과 같다(DECISIONS §10).

★ **엔진 출력의 길이를 워커가 검사한다.** `zip` 은 짧은 쪽에 맞춰 조용히
자르고, 잘린 결과는 1번 보기에 2번 번역을 붙인다. 학습 도구에서 이것은 없는
것보다 나쁘다(DECISIONS §1). 길이가 어긋나면 502 다.

★ `translations` 의 길이는 항상 `texts` 와 같다. 확장이 이 불변식을 검사하고,
어긋나면 삽입한 박스를 회수한다.

★ **엔진 실패를 500 으로 흘리면 안 된다.** 예외가 미들웨어를 건너뛰어 CORS
헤더가 빠지고, 브라우저 콘솔에는 CORS 위반으로 보고된다. 502 로 감싸 계약
형태를 지킨다.

★ 콘텐츠 스크립트의 `fetch` 는 페이지 오리진을 쓴다. CORS 미들웨어가 없으면
모든 요청이 막힌다.

### 4-1. 무엇을 번역하지 않는가

**대상 언어와 같은 문자로 쓰인 텍스트는 워커로 보내지 않는다.** 브로커가
수집 단계에서 거른다. 글자 중 한글 비율이 `KO_RATIO`(0.3) 이상이면 건너뛴다.

★ **언어 감지를 하지 않는다.** 감지는 짧은 문장에서 자주 틀리고, 외부 API 를
쓰면 항목마다 왕복이 는다. 대신 제외만 한다 — 이미 한국어인 것을 번역해도
얻을 것이 없다는 것은 판정이 아니라 확정적 사실이다.

★ **언어는 사이트나 페이지 단위로 정할 수 없다.** 한 페이지 안에 섞인다.
구글 폼은 안내문이 한글이고 보기가 섞여 있으며, Udemy 는 UI 가 한글이고
문항만 영어다. 그래서 유닛마다 본다.

★ 걸러진 유닛은 워커로 가지 않으므로 캐시도 카운터도 건드리지 않는다.

## 5. 캐시

키는 `sha256(원문)` 이다. **사이트를 키에 섞지 않는다.** 같은 문장이 여러
사이트에 나오므로, 섞으면 같은 문장을 두 번 번역한다. 사이트가 늘수록 히트율이
올라가는 구조로 둔다.

| `CACHE` | 저장소 | 용도 |
|---|---|---|
| `memory` | 프로세스 | 테스트 전용 |
| `file` | `.cache/translations.json` | 로컬 개발. 현재 값 |
| `ddb` | DynamoDB | 배포 (미구현) |

★ **캐시가 휘발이면 워커 재시작마다 전량 재번역이다.** 로컬 엔진에서는 시간
손실이지만 과금 엔진에서는 그대로 재과금이다(DECISIONS §5).

★ `ddb` 모드는 `batch_get_item` 으로 최대 100건씩 묶고 `UnprocessedKeys` 를
재시도한다. 항목마다 `get_item` 을 돌면 왕복이 항목 수만큼 난다.

## 6. 비용 가드

월 누적 문자 상한을 넘으면 번역을 거부한다. 기본값 2,000,000 은 AWS Translate
무료 티어 한도와 같다.

| 환경변수 | 기본값 | 뜻 |
|---|---|---|
| `MAX_CHARS_PER_MONTH` | 2000000 | 월 상한 |
| `MAX_TEXT_LEN` | 5000 | 단일 텍스트 상한 |

| `QUOTA_FILE` | `.cache/quota.json` | `CACHE=file` 일 때 카운터 위치 |

★ **카운터 백엔드는 `CACHE=ddb` 일 때만 원격이다.** `memory` 가 아니면
DynamoDB 로 가르면 `CACHE=file` 에서 카운터만 AWS 로 샌다(DECISIONS §10).

★ **`file` 모드는 카운터도 파일에 남긴다.** 메모리에 두면 워커 재시작마다 월
사용량이 0 이 되어 상한이 무의미하다. 캐시를 지워도 사용량은 남아야 하므로
파일을 따로 둔다.

★ **카운터를 프로세스 메모리에 두면 Lambda 에서 무효다**(DECISIONS §2).
`ddb` 모드에서는 `ConditionExpression` + `ADD` 로 조건부 원자 증가를 쓴다.
읽고-판단하고-쓰는 것이 아니라 DynamoDB 가 한 연산으로 처리하므로, 동시
실행되어도 상한을 넘지 않는다.

★ **번역 전에 예약한다.** 호출 뒤에 올리면 그 사이 요청이 같은 잔여를 보고
둘 다 통과한다. 실패 시 과다 계상되지만 과소 계상보다 안전하다.

★ **캐시 히트는 카운터를 올리지 않는다.** 과금되지 않으므로.

★ AWS Budgets 는 알림만 보내고 호출을 막지 않는다. 실제 차단은 여기서 한다.

## 7. 번역 엔진

| `ENGINE` | 대상 | 비용 | 상태 |
|---|---|---|---|
| `echo` | `[KO] 원문` | 0 | DOM · 렌더링 작업용 |
| `local` | Ollama · `exaone3.5:7.8b` | 0 | 현재 값. 상한 `OLLAMA_TIMEOUT`(700s) |
| `translate` | AWS Translate | $15/100만 자 | 구현됨. 미사용 |
| `bedrock` | Bedrock Converse · `BEDROCK_MODEL` | 모델별 토큰 과금 | **실호출 검증됨**(2026-09-14) |

★ **로컬 엔진의 배치 최적점은 3 이다**(45유닛 실측). 위반이 U자를 그려
1·2·3·6·9 에서 9·6·3·5·6 건이다. 크면 용어집이 묻히고 작으면 `BATCH_RULE` 이
빠져 환각과 문체가 돌아온다(DECISIONS §51). 확장의 `MAX_BATCH` 기본값이 그 값
이며, **그룹이 있는 경우에만 적용된다** — 그룹 없는 본문은 낱개로 나간다.

★ **`local` 과 `bedrock` 은 같은 배치 경로를 탄다.** 용어집 선택 · 배치 규약 ·
파싱 실패 시 개별 폴백은 엔진의 성질이 아니라 이 도구의 성질이므로 `_llm_batch`
하나에 있고, 엔진은 "한 프롬프트를 처리하는 함수" 만 다르다. 후처리도 공통이다.
그래서 두 엔진의 골든셋 결과가 같은 기준으로 비교된다.

★ **`bedrock` 은 `invoke_model` 이 아니라 Converse API 를 쓴다.** 요청 본문
스키마가 모델마다 다르므로 `invoke_model` 에서는 모델을 바꾸면 호출 코드를
다시 쓴다. Converse 는 그 차이를 감추므로 `BEDROCK_MODEL` 값만 바뀐다.

★ **`BEDROCK_REGION` 을 `AWS_REGION` 과 따로 둔다.** Bedrock 은 모델마다 제공
리전이 다르다. 모델 하나 때문에 캐시 · 카운터까지 다른 리전으로 옮기지 않는다.

★ Converse 에 seed 를 넘기지 않는다. 공통 필드가 아니고 모델마다 지원이
갈린다. 결정성은 `temperature 0` 에 기댄다.

★ **그리고 `temperature 0` 만으로는 고정되지 않는다.** 같은 조건 두 판에서
Nova Lite 의 어구가 갈렸다 — 위반 유닛과 종류는 같고 문장이 다르다. `local` 은
seed 를 함께 주므로 유닛 이름까지 재현된다. **재현성이 엔진마다 다르다**
(DECISIONS §65).

★ **캐시가 그 흔들림을 한 번으로 막는다.** 최초 결과를 영구 고정하므로 같은
문장이 두 번 다르게 보이지 않는다. 대신 흔들린 결과가 그대로 박제된다.

### 7-0. 엔진 비교 (45유닛 · 배치 3 · 2026-09-15)

§30 · §32 로 0 이 된 항목인데 프롬프트는 그대로였다 — 지시가 모델에게 "이것이
고유명사인가" 를 묻는 형식이어서, 그 판정이 빗나가면 목록이 있어도 안 걸렸다.

★ 정본은 `docs/bench/baseline.json` 의 `engines` 블록이며 이 표는 그 요약이다.

### 7-1-1. 후보 실측 (GTX 1660 Ti, 6GB)

| 항목 | 값 |
|---|---|
| 처리율 | 34.6자/초 (45유닛 · 배치 3) |
| 문항 하나(9유닛) | 80.7초 |
| VRAM 점유 | 4,800 / 6,144 MiB |
| 하드웨어 배치 | 24%/76% CPU/GPU — **온전히 GPU 에 올라가지 않는다** |
| 모델 콜드 로딩 | 87.6초 |
| 재현성 | `temperature 0` + `seed 42`. **같은 하드웨어 배치 · 같은 배치 크기에서만** |
| 위반 | 유닛 3 · 종류 4 (용어 표기). 환각 · 문체 · 고유명사 0 |

★ **배치 크기가 결과를 정한다.** 위반이 1·2·3·6·9 에서 9·6·3·5·6 으로 U자를
그리므로 기준선에 배치를 함께 적고 지문에도 넣는다(DECISIONS §51 · §57).
속도는 배치에 거의 무관하다 — 같은 구간에서 38.4~33.6자/초다.

★ **항목마다 따로 호출하던 때는 페이지당 3~4분이었다.** 한 프롬프트로 묶고
지어낸 답이 후처리에서 잘리면서 80초가 되었다(DECISIONS §20).

★ **오프로딩되면 결과가 달라진다.** 모델이 부분적으로 CPU 로 내려가면 속도만
떨어지는 것이 아니라 번역이 바뀐다 — CPU 와 GPU 는 부동소수점 누적 순서가 달라
`temperature 0` 이어도 토큰 선택이 갈린다. 2026-09-13 실측에서 같은 지문으로
위반이 2 → 4 가 되었다(DECISIONS §35). 러너가 이것을 감지해 경고한다.

★ **이 기계에서 오프로딩은 정상 상태다.** VRAM 6GB 에 7.8B 모델이라 온전히
올라가지 않는다. 가중치만이 아니라 KV 캐시와 컴퓨트 버퍼도 VRAM 을 쓰므로,
VRAM 이 1.4GB 남아 있어도 일부 레이어가 CPU 에 남는다. 볼 것은 오프로딩 여부가
아니라 **배치가 기준선과 같은지**다(DECISIONS §36).

★ **느린 것과 오프로딩은 다른 문제다.** 메모리 압박이 있으면 느려진다 — 여유가
173MB 까지 떨어진 실행이 16자/초였다. 메모리가 넉넉하면 오프로딩된 채로도
35자/초가 나온다. 다른 WSL 터미널의 작업도 같은 커널과 페이지 캐시를 쓴다.

★ **콜드 로딩은 페이지 시간에 들어 있지 않다.** 웜업이 집계 밖에서 잰 값이다
(DECISIONS §27). 다만 사용자에게는 섞여 보인다 — 모델이 내려간 뒤 첫 페이지는
84초가 아니라 149초다.

★ **웜 실행 2회가 177.8s 와 168.5s 로 5.5% 갈렸다.** 이보다 작은 차이로 엔진을
고르면 노이즈로 고르는 것이다.

★ 원시 수치는 `docs/bench/baseline.json` 에 있다. 이 표는 사람이 읽는
요약이고 그 파일은 기계가 비교하는 값이다. 숫자를 고칠 때 양쪽을 함께
고친다.

★ **위 표의 `재현성` 행은 한동안 표 밖에 떨어져 있었다.** ★ 항목 뒤에 놓여
표가 거기서 끊기고 그 행만 본문으로 렌더됐다. 표를 고칠 때 행을 아래에
덧붙이면서 경계를 넘은 것이다.

★ **실사용 불가 판정이다.** 품질은 합격이나 소비자 GPU 의 처리 속도가 천장이다
(DECISIONS §6). 로컬 엔진은 오프라인 개발과 비교 기준선으로 남긴다.

### 7-2. 프롬프트 규칙

용어 보존을 **학습이 아니라 지시로** 한다. AWS Custom Terminology 와 달리 이
프롬프트는 어느 엔진에나 그대로 옮겨간다.

1. AWS 서비스명 · API명 · 파라미터명은 영어 유지
2. 그 뒤에 한국어 조사를 자연스럽게 붙인다
3. 합니다체
4. 번역만 출력한다
5. 원문에 없는 내용을 추가하지 않는다
6. 출력 길이를 원문에 가깝게 유지한다

★ 1번만 있으면 서비스명이 토큰 덩어리로 취급되어 조사가 붙지 않는다.
2번이 없으면 "Kinesis Data Streams 거의 즉시…" 같은 비문이 나온다.

★ 5번은 완전히 먹지 않는다. 긴 지문에서 모델이 번역을 마친 뒤 스스로 답을
이어 붙이는 경우가 남아 있다(PLAN §2-2).

## 8. 용어집

`worker/app/glossary/*.json` 이 도메인별 용어 매핑을 담는다. 현재 `aws.json`
35개.

**어느 용어집을 쓸지 코드가 판단하지 않는다.** 모든 용어집을 훑어 원문에 실제로
나타난 용어가 가장 많은 것을 고른다. 2개 미만이면 도메인으로 보지 않는다.

### 8-1. 항등 항목 — 영어로 유지할 이름

**표기가 en 과 같은 항목은 "번역하지 말라" 는 뜻이다.** `data catalog` 의 값이
`Data Catalog` 이면 그 이름은 영어로 남는다.

★ **규칙 1 과 용어집은 같은 종류의 지시다.** 둘 다 "이 용어는 이렇게 써라" 를
말하는데, 한쪽은 프롬프트의 예시로 다른 한쪽은 데이터로 있었다. 나뉘어 있으니
부딪쳤다 — 복합 고유명사의 뒷말이 등재어이면 모델이 더 구체적인 지시인 용어집을
따라 그 부분만 한글로 옮겼다(DECISIONS §30).

★ **예시가 아니라 데이터다.** 규칙 1 의 `e.g.` 목록은 모델이 목록으로 취급해
거기 없는 이름을 놓친다. 항등 항목은 원문에 실제로 나타난 것만 배치마다 실리므로
등재가 늘어도 프롬프트가 자라지 않는다.

★ **번역 목록과 줄을 나눠 싣는다.** `Data Catalog -> Data Catalog` 는 사람에게는
자명하나 모델에게는 번역 지시 형식 그대로다. 나머지 항목과 같은 자리에 놓이면
무엇을 하라는 것인지 흐려진다.

★ **키는 소문자로 적는다.** 매칭이 `blob.lower()` 에서 돌므로 대문자 키는 영영
걸리지 않는다. 등재해도 조용히 아무것도 하지 않는다(DECISIONS §21). 원하는 표기는
값에 적는다. 테스트가 이것을 지킨다.

★ **검사도 같은 함수로 고른다.** 골든셋의 용어 검사는 케이스에 적힌 목록이
아니라 `glossary._hits` 가 원문에서 고른 것을 본다. 지시하는 목록과 검사하는
목록이 다르면 차이나는 자리는 지시만 하고 검사하지 않는다(DECISIONS §49).

★ 등재 기준은 변하지 않는다 — **이미 발견한 오류만 넣는다.** 깨진 적 없는 이름을
미리 채우면 커버리지 경쟁이 되고, 그것은 이 용어집이 하지 않기로 한 일이다.

| 상수 | 값 | 뜻 |
|---|---|---|
| `MIN_HITS` | 2 | 맞은 용어 수의 하한 |
| `MIN_SCORE` | 5 | 가중 점수의 하한 |
| `MULTIWORD_W` | 4 | 여러 낱말로 된 용어의 가중치 |
| `MAX_TERMS` | 25 | 프롬프트에 실을 상한 |

★ **맞은 개수만으로 판정하면 오탐이 난다.** `object` · `policy` · `role` ·
`node` 는 등재어지만 평범한 영어 낱말이라 무관한 산문에서도 두어 개는 쉽게
맞는다. 여러 낱말로 된 용어(`partition key`)는 우연히 맞을 수 없으므로 신호가
강하다. 한 낱말 넷으로는 하한을 넘지 못한다(DECISIONS §10).

★ **맞은 용어만 프롬프트에 싣는다.** 전부 실으면 프롬프트가 길어져 느려지고,
쓰이지 않을 항목이 모델의 주의를 나눠 가진다.

★ 어미 변화를 표제어 하나로 흡수한다(`record` 가 `records` · `recording` 에
걸린다). 용어집에 단복수를 따로 넣는 방식은 끝이 없다.

★ **용어집이 없어도 번역은 정상 동작한다.** §7-2 의 보편 규칙이 따로 있기
때문이다. 용어집은 외부 관행과 표기를 맞추는 정련이지 번역의 전제가 아니다.
검증 가능한 불변식은 "등재 용어의 위반 0" 이지 "번역 정확도 100%" 가 아니다.

★ 새 도메인은 JSON 파일 하나 추가로 끝나고 코드는 건드리지 않는다.

## 9. 권한 모델

| 항목 | 값 |
|---|---|
| `permissions` | `storage`, `scripting`, `activeTab` |
| `optional_host_permissions` | `<all_urls>` |
| `action.default_popup` | `popup.html` |

**사이트 목록을 코드에 들지 않는다.** `host_permissions` 도 `content_scripts`
도 두지 않는다. 모든 사이트가 같은 경로를 탄다 — 아이콘 클릭 → 팝업 → "이
사이트에서 켜기" → 해당 오리진 권한 요청 → 승인되면 주입하고, **그 사이트는
이후 방문부터 자동**으로 동작한다.

★ **`default_popup` 이 있으면 `chrome.action.onClicked` 는 발화하지 않는다.**
그래서 권한 요청과 주입이 `background.js` 에서 팝업으로 옮겨 왔다. 발화하지
않는 리스너를 남기지 않는다 — 다음 사람이 그것이 도는 줄 안다(DECISIONS §38).

★ **팝업의 버튼 클릭도 사용자 제스처다.** `permissions.request` 가 거기서
성립한다. 다만 제약은 그대로여서, 요청 전에 `await` 가 하나라도 있으면 문맥을
잃는다. **팝업이 열릴 때 탭과 권한 상태를 미리 조회해 두고**, 클릭 핸들러에서는
콜백 형태로 요청만 한다(DECISIONS §13).

★ 전에는 Udemy 만 `content_scripts` 로 자동 주입하고 `background.js` 의 제외
목록으로 걸렀다. 같은 사실이 `host_permissions` · `matches` · `ST_STATIC` 세
곳에 서로 다른 문법으로 살았고, 한쪽만 고치면 조용히 어긋났다. 특별대우를
없애니 세 곳이 모두 사라졌다(DECISIONS §14).

★ **승인 클릭은 사이트당 두 번이다.** 크롬의 확장 권한 확인과 오리진 부여가
따로 뜬다. `host_permissions` 에 `<all_urls>` 를 박으면 설치 시 한 번으로
줄지만, 설치할 때 모든 사이트 접근을 요구하는 확장이 된다. 사이트당 1회성
비용을 택하고 최소 권한을 유지한다.

★ **`permissions.request` 앞에 `await` 를 두지 않는다.** 대기 한 번에 사용자
제스처 문맥이 끊겨 요청이 거부된다. 이미 가진 권한이면 `request` 가 창 없이
참으로 해소되므로 `contains` 로 미리 물을 이유도 없다(DECISIONS §13).

★ 어댑터는 재주입에 대비해 같은 `name` 이 이미 등록되어 있으면 push 하지
않는다. 최상위 `const` 도 쓰지 않는다. 재선언은 `SyntaxError` 다.

★ **팝업과 `state.js` 는 그 규약의 대상이 아니다.** 주입되지 않으므로 재선언이
일어나지 않는다. `doctor.sh` 가 `ST_FILES` 를 읽어 주입 파일만 검사한다
(DECISIONS §22).

★ **어댑터 수집은 jsdom 으로 검사한다**(`extension/tests/`). 직접 만든 스텁은
셀렉터 파서를 다시 만들어야 하고, 그 파서가 브라우저와 다르면 테스트가
통과하면서 틀린다(DECISIONS §21 · §47).

★ **검사 대상은 수집 구조뿐이다.** 몇 개 모였는지 · 어떻게 묶였는지 · 어디에
위임했는지를 본다. `innerText` 가 jsdom 에 없어 하네스가 `textContent` 로
채우는데 그 대체는 숨김 요소를 포함하고 `<br>` 을 개행으로 만들지 않는다 —
**텍스트가 정확히 무엇인지는 픽스처로 본다**(§11-5).

★ jsdom 이 없으면 확장 검사가 전부 건너뛰어진다. `doctor` 가 그 건수를
`WARN` 으로 적는다 — 통과로 세면 수집이 깨져도 모른다.

★ **브로커도 같은 하네스에 올린다.** 흉내내는 것은 `chrome.storage` 와 `fetch`
둘뿐이고 `MutationObserver` · 타이머 · `AbortController` 는 jsdom 과 Node 가
이미 한다. **흉내가 적을수록 실제와 어긋날 자리가 적다**(DECISIONS §48).

★ **전역과 창은 다르다.** 주입되는 파일은 전역에서 찾으므로 jsdom 창 안에만
있는 것은 하네스가 전역으로 옮겨 준다. 빠뜨리면 죽거나 조용히 빈손이 된다.

★ **브로커는 올라가는 순간 순회를 시작한다.** 하네스가 타이머를 잡아 핸들을
돌려주고 호출한 쪽이 끊는다. 끊지 않으면 테스트가 끝나도 프로세스가 죽지 않는다.

## 10. 표시 제어

토글은 **페이지에 DOM 요소를 두지 않는다.** 고정 위치 버튼은 사이트마다 남의
UI 를 가린다. `Alt+K` 로 `html.st-off` 클래스를 전환하고 상태를
`chrome.storage.local` 에 남긴다. 팝업에도 같은 토글을 두어 단축키를 모르는
사용자가 끌 수 있게 한다 — 저장하는 값과 전환하는 클래스가 같으므로 경로는
하나다. 판정은 `e.key` 가 아니라 `e.code` 로 한다. `e.key` 는 레이아웃과
데드키에 흔들린다.

### 10-1. 번역 박스

`extension/content.css` 한 파일이 그린다.

★ **`!important` 를 쓰지 않는다.** 클래스를 두 번 적어 명시도 `(0,2,0)` 으로
남의 규칙을 이긴다. `!important` 로 이기면 그 위에 덮을 방법이 없어진다.

★ **색은 변수로 두고 `prefers-color-scheme` 으로 갈린다.** 어두운 테마에서는
배경을 밝히지 않고 한 단계만 띄운다 — 검은 화면 위 흰 상자는 문항보다 번역이
먼저 눈에 들어온다.

★ **글꼴을 싣는다.** 윈도우 크롬에서 한글은 `Malgun Gothic` 으로 떨어지고
그것이 화면을 낡아 보이게 하는 가장 큰 이유였다. **시스템에 없는 글꼴을 이름으로만
적는 것은 적지 않은 것과 같다.** Pretendard 가변 글꼴을 `wght 400-700` 으로
인스턴싱하고 라틴 + 상용 한글로 부분집합해 603KB 로 싣는다(원본 2.0MB). 없는
음절은 시스템 글꼴로 떨어지므로 깨지지 않는다.

★ **SIL OFL 1.1 이다.** 사본을 `extension/fonts/LICENSE.txt` 에 함께 둔다 —
재배포 조건이고 웹스토어 심사에서도 묻는다.

★ **`web_accessible_resources` 에 등록한다.** 콘텐츠 스크립트가 주입한 CSS 의
상대 경로는 확장 오리진으로 풀리는데, 페이지가 그 파일을 읽으려면 공개돼 있어야
한다.

★ **글자 크기가 `px` 다.** `em` 은 부모를 따라가는데 문항 · 보기 · 해설의 부모
크기가 달라 같은 번역이 자리마다 다른 크기로 나왔다.

★ **이름표는 칩이다**(`::before` 의 `한글`). 강조색 배경에 강조색 글자로 두어
번역이 시작되는 자리를 한눈에 잡는다. DOM 이 아닌 이유는 브로커가
`textContent` 를 갈아 끼울 때 같이 지워지기 때문이다.

★ **색도 사이트에서 뽑는다.** 브로커가 배경과 글자색을 읽어 `--st-site-*` 로
넘기고, 면 · 테두리 · 뼈대가 거기서 파생된다. **사이트의 CSS 를 알 필요가
없다** — 계산된 값만 읽는다. 대비가 4.5 미만이면 아무것도 넘기지 않고
`content.css` 의 기본값이 선다(§59).

★ **테마를 추측하지 않고 잰다.** 브로커가 앵커에서 위로 올라가며 실제로
칠해진 첫 배경색을 찾아 상대 휘도를 구하고 `html[data-st-theme]` 에 남긴다.
CSS 는 그 속성만 본다. `prefers-color-scheme` 은 OS 설정이라 크롬이 어두운데
사이트가 밝으면 **흰 바탕에 흰 글씨**가 난다(DECISIONS §92).

★ **투명한 배경은 건너뛴다.** 대부분의 요소가 `rgba(0,0,0,0)` 이고 그것을
검정으로 읽으면 모든 사이트가 어두운 것이 된다.

★ **분기마다 세우는 방법이 다르다.** 밝은 면은 그림자로 띄우고 어두운 면은
안쪽 하이라이트로 세운다 — **검은 바탕에서 그림자는 아무것도 하지 않는다.**

★ **번역이 주인공이다.** 원문보다 무겁다. 원문은 대조용으로 곁에 있는
것이고 눈이 먼저 닿아야 하는 쪽은 한국어다.

★ **이름표를 DOM 이 아니라 `::before` 로 둔다.** 요소를 늘리면 브로커가
`textContent` 를 갈아 끼울 때 같이 지워지고 스크립트와 스타일이 한 쌍 더 생긴다.

★ **기다리는 동안 뼈대를 세운다.** 이름표가 `번역 중` 으로 바뀌고 본문 자리에
줄 세 개가 놓인다. **글자를 흘리지 않는 이유**는 번역이 도착할 때 높이가 튀지
않게 하기 위해서다. `prefers-reduced-motion` 이면 깜빡이지 않고 뼈대만 남는다.

★ **어댑터의 `decorate` 가 아직 인라인 `!important` 로 세 속성을 덮는다.**
CSS 와 값이 같아 충돌하지는 않으나 **스타일이 두 곳에 산다**(DECISIONS §91).

### 10-2. 팝업

`extension/popup.css` 가 그린다. 마크업은 건드리지 않는다 — `popup.js` 가
id 로 붙잡으므로 요소를 늘리면 스크립트와 한 쌍이 더 생긴다.

★ **값을 변수로 두고 라이트 · 다크가 같은 규칙을 쓴다.** 번역 박스와 같은
이유다(DECISIONS §91).

★ **체크박스 하나를 스위치로 그린다.** 켜짐 · 꺼짐이 한눈에 갈려야 하는
자리이고 기본 체크박스는 팝업에서 너무 작다.

★ **상태를 색만으로 말하지 않는다.** 앞의 점이 색을 구별하기 어려운 눈에도
상태를 보이게 하고, 문장이 줄바꿈해도 시작점을 잡아 준다.

★ **행동 두 개만 강조한다.** `이 사이트에서 켜기` 와 `저장` 이 이 화면의
행동이고 나머지는 배경이다.

★ **`extension/preview.html` 로 본다.** 브라우저로 열면 라이트 · 다크 ·
문항 · 보기 · 로딩 · 링크가 한 화면에 늘어선다. `content.css` 를 그대로 읽으므로
고치고 새로고침하면 바로 보이고 **확장 동기화가 필요 없다.** 동기화 대상에서는
뺀다 — 크롬은 폴더 안의 모든 파일을 확장의 일부로 본다.

★ **그려진 노드를 보는 검사가 없다.** 확장 검사 43건은 실패 판정과 클라이언트
계약만 본다. 로딩 클래스가 붙고 떨어지는 것은 **눈으로만 확인됐다**.

URL 은 번역 대상에서 분리해 클릭 가능한 링크로 되붙인다. 번역기에 넣으면
경로가 깨지고, 깨진 채로 캐시에 박제된다. 삽입은 `innerHTML` 이 아니라 DOM
API 로 한다.

## 11. 운영

### 11-1. 로컬 실행

```bash
bash tools/run_ollama.sh > /tmp/ollama.log 2>&1 &   # ENGINE=local 일 때만
bash tools/preflight.sh                             # 엔진 전제만 본다. 띄우지 않는다
bash tools/run_worker.sh                            # .env 를 읽어 워커 기동
bash tools/sync_ext.sh                              # 확장을 SSD 로 내보낸다

ENGINE=echo bash tools/run_worker.sh                # 이번 한 번만 다른 설정으로
```

★ **셸에 앞세운 지정이 `.env` 를 이긴다.** 한 번만 다른 엔진으로 띄우려고
`.env` 를 고쳤다 되돌리면 되돌리는 것을 잊는다(DECISIONS §40). 로더는
`tools/lib/env.sh` 하나이고 모든 도구가 그것을 쓴다.

★ **`~/.bashrc` 에 박아 두는 것은 여전히 금지다.** 그것은 일회성이 아니라
영구 오염이고 `doctor.sh` 가 검사한다(D-0066).

확장은 `chrome://extensions` → 개발자 모드 → 압축해제된 확장 프로그램을 로드 →
`F:\projects\thoth\ext-build`.

★ **크롬은 `\\wsl$` 같은 네트워크 경로에서 압축해제 확장을 로드하지 못한다.**
정본은 WSL 의 `extension/` 이고 SSD 쪽은 `--delete` 로 덮어쓰는 파생물이다.
거기서 편집하면 다음 동기화에 사라진다.

★ `rsync -a` 는 `-p` 를 포함해 DrvFs 에서 권한 설정에 실패한다.
`-rlt --no-perms --no-owner --no-group` 을 쓴다.

★ **`doctor` 가 사본이 정본과 같은지 본다.** 도구가 있어도 돌리지 않으면
어긋나고, 어긋난 것이 눈에 보이는 쪽이면 원인을 코드에서 찾게 된다
(DECISIONS §92). 사본이 없거나 마운트가 안 붙었으면 `WARN` 이다 — 못 잰 것이지
틀린 것이 아니다.

★ **`sync_ext.sh` 가 `src/config.local.js` 를 파생물에만 채운다.** `.env` 의
`EXT_ENDPOINT` · `EXT_TOKEN` 을 읽는다. 저장소의 원본은 언제나 비어 있으므로
공개 저장소에 엔드포인트도 토큰도 나가지 않는다(§84). 채워 두면 팝업에 손으로
넣을 일이 없고, **`chrome.storage` 의 값이 언제나 이것을 이긴다.**

★ **`WORKER_TOKEN` 과 다른 키다.** 그쪽은 로컬 워커가 **요구할** 토큰이고
채우면 골든셋과 스모크가 401 을 받는다.

### 11-2. 설정

`.env` 가 실값, `.env.example` 이 **키 목록의 정본**이다.
`python-dotenv` 같은 의존성을 쓰지 않고 셸이 `set -a; . ./.env; set +a` 로 읽는다.

★ **프로젝트 설정을 셸에 export 하지 않는다.** 하면 `.env` 가 조용히 무시된다.

★ `--reload` 는 `.py` 변경만 감지한다. `.env` 를 고치면 워커를 새로 띄운다.

### 11-3. 점검

```bash
bash tools/doctor.sh          # 전부
bash tools/doctor.sh --repo   # 저장소 불변식만 (커밋 훅이 쓰는 범위)
```

비밀값 · `.env` 키 정합 · 셸 오염 · 훅 배선 · 홈 규약 · 산출물 · 엔진 전제 ·
모델 위생 · 셸 문법 · 파이썬 린트 · 문서 규약 · 문서 건수를 검사하고, 확장
테스트와 워커 테스트 <!--count:worker_tests-->270건을 함께 돌린다.

**등급이 셋이다.**

| 등급 | 뜻 | 커밋 |
|---|---|---|
| `FAIL` | 저장소나 보안 불변식을 어겼다 | 막는다 |
| `WARN` | 지금 작업하려면 손봐야 한다 | 통과한다 |
| `SKIP` | 잴 수 없었다 | 통과한다 |

★ **등급이 하나뿐이면 모든 검사가 최악의 검사와 같은 힘을 갖는다.** 문서 세
줄을 고치는 커밋이 ollama 미기동으로 막혔다 — 번역을 돌릴 일이 없는데도 그랬다
(DECISIONS §46).

★ **새 검사를 넣을 때 "이것이 커밋을 막을 일인가" 를 먼저 묻는다.** 막는 것은
저장소를 틀리게 하거나 비밀을 새게 하는 것뿐이다. 느려지는 것 · 디스크를 먹는
것 · 지금 못 돌아가는 것은 `WARN` 이다.

★ **막는 일은 그것이 실제로 필요한 자리에서 한다.** 엔진 전제가 깨진 것은
`doctor` 가 `WARN` 으로 알리고, `run_worker.sh` 가 기동 전에 죽는다. 실패는
그것이 일어난 자리에서 알린다(DECISIONS §37).

★ **`doctor` 는 전검사를 `--cheap` 으로 부른다.** 커밋마다 도는 자리에서
`bedrock` 확인은 실제 호출이라 네트워크와 비용이 든다. 재지 않은 엔진은
`not_measured` 로 돌아오고 `SKIP` 으로 적힌다 — **통과가 아니다**
(DECISIONS §59).

★ **기계 설정 검사를 커밋을 막는 자리에 두지 않는다.** 홈 규약 · 셸 오염 ·
SSD 경로 · 모델 목록은 이 저장소의 불변식이 아니라 한 작업 기계의 불변식이다.
거기 두면 다른 기계에서 관계없는 이유로 커밋이 막힌다. `.githooks/pre-commit`
은 `--repo` 로 부른다.

★ **`THOTH_SSD_ROOT` 는 두 경우를 가른다.** 키가 `.env` 에 없으면 설정이 틀린
것이라 `FAIL` 이고, 키는 있는데 경로가 없으면 마운트가 안 붙은 것이라 `WARN`
이다. 한 줄로 묶으면 노트북을 도킹하지 않았다는 이유로 커밋이 막힌다.

★ **정본이 하나인 것과 모든 자리에서 똑같이 구는 것은 다르다.** CI 는 넘어갈
수 없고 로컬은 넘어갈 수 있다. jsdom 이 없으면 `doctor` 는 `WARN` 으로 알리지만
CI 는 `npm ci` 로 설치하고 건너뛴 건수가 0 인지 따로 확인한다 — 건너뛰면 초록불인
채로 수집이 깨진다(DECISIONS §54).

★ **검사의 정본은 `tools/doctor.sh` 하나다.** 훅도 CI 도 같은 진입점을
부른다. CI 가 같은 검사를 다시 구현하면 같은 사실이 두 곳에 살고 한쪽만
고쳐질 때 조용히 어긋난다(DECISIONS §14). **검사를 늘릴 때 `doctor.sh` 만
고치면 양쪽에 반영된다.**

| 층 | 무엇을 부르나 | 우회 |
|---|---|---|
| 전역 훅 | 자격증명 검사 → 저장소 훅 | `--no-verify` |
| 저장소 훅 | `doctor.sh --repo` | `--no-verify` |
| CI `verify` | **같은 `doctor.sh --repo`** | 불가 |
| CI `smoke` | `tools/smoke.sh` | 불가 |
| CI `gitleaks` | 액션 | 불가 |

★ **훅은 `--no-verify` 로 넘어간다.** 그래서 CI 가 따로 있다. 둘은 중복이
아니라 우회 가능성이 다른 두 층이다.

★ **CI 에서 아무것도 하지 않는 검사가 있다.** DECISIONS 추가 전용 검사는
작업 트리와 HEAD 를 비교하는데, CI 에서는 둘이 언제나 같으므로 항상
통과한다. 그 검사의 정본은 훅이다(DECISIONS §21).

★ **새 검사는 기존 자산에 소급 적용해 0 건으로 만든 뒤 켠다.** 대량으로
실패하면 십중팔구 검사가 틀렸다. 2026-09-13 에 검사가 다섯 번 틀렸고
전부 그렇게 잡혔다(DECISIONS §19 · §21 · §22).

★ **로컬 `core.hooksPath` 를 설정하지 않는다.** 설정하면 전역 훅이 아예 돌지
않아 자격증명 검사가 꺼진다. 전역 `pre-commit` 이 저장소 훅을 찾아 불러준다.

### 11-4. 골든셋

```bash
ENGINE=<엔진> CACHE_FILE=/tmp/bench-cache.json bash tools/run_worker.sh &
python3 tools/bench_golden.py --json out.json
```

번역의 정확도가 아니라 검증 가능한 불변식을 잰다 — 고유명사 유지 · 용어집
표기 · 물음표 보존 · 길이 비율 · 합니다체. 측정할 수 없는 목표는 세우지
않는다(§8).

★ **캐시를 비우는 대신 딴 파일로 보낸다.** 지우면 번역이 버려지고 과금 엔진
에서는 재과금이다(DECISIONS §5). 이번 실행만 `CACHE_FILE` 을 앞세우면 캐시는
그대로 두고 히트만 없앤다.

★ **캐시 히트 실행은 측정이 아니다.** 번역을 하지 않으므로 0.1초가 나온다.
2026-09-14 에 실제로 그렇게 `199236자/초` 가 찍혔다. **러너가 히트를 세고
하나라도 있으면 처리율을 아예 적지 않는다** — 숫자를 적고 옆에 경고를 붙이면
그 숫자가 인용된다(DECISIONS §64).

★ **속도만이 아니라 위반도 그 엔진의 값이 아니다.** 캐시 키는 `sha256(원문)`
하나라 엔진을 섞지 않으므로, 히트한 문장은 전에 다른 엔진이 번역한 것이다.

★ **배치 기본값은 기준선에서 읽는다.** 러너가 `docs/bench/baseline.json` 의
`config.batch` 를 쓴다. 전에는 러너 기본이 9 이고 기준선이 3 이라, `--batch` 를
빠뜨린 실행이 조용히 다른 조건에서 쟀다.

★ **결과 파일이 엔진을 적는다.** 러너가 `/health` 에 물어 `engine` 을 남긴다.
파일 이름과 사람의 기억이 그것을 대신하면 언젠가 갈린다.

★ **비워야 하는 것이 캐시만은 아니다.** 콜드 실행의 첫 배치에는 모델 로딩이
섞인다. 러너가 웜업을 먼저 태우고 그 시간을 집계 밖에 둔다. 재는 사람이
직전에 무엇을 했는지가 수치를 정하면 그것은 측정이 아니다(DECISIONS §27).
콜드 로딩 비용 자체를 재려면 `--no-warmup` 을 쓰고, 그 값은 기준선에 넣지
않는다.

★ **원문을 저장소에 넣지 않는다.** 모양만 닮은 창작 지문을 쓴다. 길이 분포와
용어 밀도가 실제 워크로드와 같아야 하며, 맞출 값은
`worker/tests/golden/README.md` 에 있다.

★ **배치별 비교는 `bench_batch.sh` 로 한다.** 여유 메모리 · ollama 기동 ·
캐시 순서 · 판 중 스왑을 코드가 본다. 조건을 사람이 기억해서 확인하면 잊는
날이 오고, 그 날 잰 값은 다른 작업을 잰 것이다(DECISIONS §50).

★ **위반과 속도는 조건이 다르다.** 위반은 `temperature 0` 이라 배치가 같으면
결정적이고 메모리와 무관하다. 속도만 조건을 타므로 한 판에서 위반은 쓰고
속도는 버릴 수 있다.

★ **기준선은 한 파일에 엔진 키를 둔다** — `docs/bench/baseline.json` 의
`engines.<이름>`. 엔진마다 파일을 나누면 비교가 목적인 정본이 갈라져 대조할 때
둘을 열어야 한다. 말뭉치(`golden`)와 엔진이 정하지 않는 설정(`config`)만 블록
밖에 있다.

★ **배치와 지문은 엔진 블록 안에 있다.** 호스팅의 최적 배치는 로컬과 다를 수
있고(PLAN §2-2 #45), 그때 그 값은 그 엔진에만 들어간다.

★ **러너가 지문을 기준선과 대조한다.** 전에는 찍어만 두고 아무와도 비교하지
않았다. 정본이 있는데 대조하지 않으면 정본이 아니다(DECISIONS §65).

★ **호스팅 엔진에서는 로컬 환경을 재지 않는다.** CPU/GPU 배치 · VRAM · 스왑은
ollama 가 이 기계에서 돌 때만 뜻이 있다. 스왑 6400MB 와 123MB 인 두 판이 0.2%
안쪽으로 같았으므로, 그 수치를 남기면 읽는 사람이 없는 상관을 찾는다.

### 11-4-1. 검사 축

| | |
|---|---|
| `keep` | 고유명사 · API명이 영어로 남는가 (§7-2 규칙 1) |
| `term` | 등재 용어가 등재 표기를 쓰는가 (§8) |
| 물음표 | 원문이 물으면 번역도 묻는가 |
| 길이 | 0.44~0.53 이 정상. 벗어나면 덧붙임 · 누락 |
| 합니다체 | `니다` · `니까` 로 끝나는가 |
| **어미** | **어간과 어미가 맞는가** |
| 한글 | 번역이 되긴 했는가 |

★ **`습니다` · `습니까` 는 자음 어간에만 붙는다.** 어간이 모음이나 `ㄹ` 로
끝나면 `ㅂ니다` 꼴이다 — 하다→합니다, 만들다→만듭니다. `할습니까` · `되습니다`
는 한국어에 없는 활용이며, 2026-09-16 실사용에서 실제로 났는데 **골든셋 45유닛은
위반 3으로 조용했다**(DECISIONS §93).

★ **재는 자가 없으면 유닛을 늘려도 안 잡힌다.** 원문을 증강하기 전에 축이
맞는지 본다.

★ **모델에게 묻지 않는다.** 결정적으로 갈리는 것을 LLM 으로 판정하면 호출이
두 배가 되고 판정도 흔들린다.

### 11-5. 어댑터 픽스처

```bash
python3 -m http.server 8099 -d extension/tests/fixtures > /tmp/fx.log 2>&1 &
ENGINE=echo bash tools/run_worker.sh > /tmp/w.log 2>&1 &
```

`http://127.0.0.1:8099/radio.html` 에서 `standard` 의 두 수집 경로를 가른다.

★ **`file://` 은 주입이 막힌다.** 서버로 띄워야 한다.

★ **`ENGINE=echo` 로 띄운다.** 확인할 것은 번역 품질이 아니라 수집과 그룹핑이고,
`echo` 는 GPU 를 쓰지 않아 즉시 답한다. `.env` 를 고치지 않아도 되는 이유는
로더가 셸 지정을 먼저 보기 때문이다(DECISIONS §40).

★ **캐시를 비우고 본다.** 같은 문장이 다른 엔진으로 이미 번역돼 있으면 히트로
나와 엔진을 바꾼 의미가 없다.

**픽스처가 둘이다.**

| 파일 | 보는 것 |
|---|---|
| `radio.html` | 어느 수집 경로가 도는가 — ARIA · 네이티브 라디오 |
| `innertext.html` | 뽑힌 글자가 맞는가 — 하네스가 볼 수 없는 자리 |

★ **`innertext.html` 은 하네스가 볼 수 없는 것만 모았다.** 어댑터 테스트는
jsdom 위에서 돌고 `innerText` 가 없어 `textContent` 로 채우는데, 그 둘은 숨긴
글자 · `<br>` · `<script>` 내용 · 공백 처리에서 갈린다(DECISIONS §47). 각
항목에 기대값을 적어 두었으므로 번역 박스와 대조한다.

★ **픽스처는 실사이트를 대신하지 않는다.** 통제된 마크업이므로 여기서 도는
것이 실제 페이지에서도 돈다는 보장이 없다. 실사이트에서 안 돌 때 코드 문제인지
마크업 문제인지 가르는 기준으로 쓴다.

### 11-6. 내보내기

```bash
bash tools/ship.sh "커밋 메시지"      # doctor → 문서 대조 → 커밋 → 푸시 안내
bash tools/ship.sh --dry "메시지"     # 푸시 직전까지만
git push && python3 tools/sweep.py --fix
```

★ **바꿀 것이 없으면 시작하지 않는다.** 작업 트리가 깨끗하면 한 줄로 멈추고
패치를 받았는지 묻는다. 긴 절차는 가장 싼 확인을 맨 앞에 둔다 — `doctor` 는
수십 초가 들고 `git status` 는 순식간이다(DECISIONS §52).

★ **커밋 실패 이유를 단정하지 않는다.** 커밋할 것이 없음 · 신원 없음 · 훅이
막음은 대응이 다르다. 모르는 경우에는 출력을 보여주고 그것을 보라고 한다.

★ **무조건 도는 넷만 묶는다.** 조건부 단계(패치 적용 · `.env` 키 추가 · 확장
동기화)는 넣지 않는다 — 이미 각 도구가 그 자리에서 알려주고, 넣으면 도구가
상황을 판단해야 해서 커진다. 2026-09-13 세션에서 빠뜨린 셋은 **전부 무조건
쪽**이었다(DECISIONS §43).

★ **문서 대조는 기계가 볼 수 있는 만큼만 본다.** 내용이 코드와 맞는지는 사람이
본다. 기계가 아는 것은 **안 봤다는 사실**이다 — 코드가 바뀌었는데 `docs/` 와
`README` 가 그대로면 멈추고 묻는다.

★ **푸시는 자동으로 하지 않는다.** 무엇이 나가는지 보여주고 사람이 친다.
`--no-verify` 도 받지 않는다 — 급할 때 넘기는 문을 만들면 급할 때 넘긴다.

★ `doctor` 는 `ship` 을 모른다. 상위 도구가 하위 검사 사슬에 들어가면 순환이
된다. `doctor` 에 `--ship` 같은 인자를 두지 않는 것이 그 경계다.

### 11-7. 위생

푸시 뒤에 돌린다. **이 저장소가 저장소 밖에 남긴 것만** 본다.

```bash
bash tools/scan.sh > /tmp/scan.txt    # 실정을 잰다. 지우지 않는다
python3 tools/sweep.py                # 흔적을 센다
python3 tools/sweep.py --fix          # 근거가 확실한 것만 지운다
```

| 대상 | 판정 근거 |
|---|---|
| `TMPDIR` 의 흔적 | 이름. 그것을 쓰는 프로세스가 떠 있으면 남긴다 |
| 수신함(`WIN_DOWNLOADS`)의 패치 | 영수증 → 역적용 → 정방향 순. 셋 다 아니면 남긴다 |
| uv 캐시 | `uv.lock` 차집합. 이웃과 겹치는 것은 남긴다 |

★ **저장소 안에는 도구를 두지 않는다.** 실측에서 300KB 였다. `git clean -Xfd`
가 이미 있고 `doctor` 가 건수만 보고한다(DECISIONS §42).

★ **겹치는 캐시는 남긴다.** 이웃 저장소도 쓰는 패키지를 지우면 남의 재설치가
느려진다. 내 것이 아닌 것을 치우는 것은 위생이 아니다.

★ **이웃은 `uv.lock` 을 가진 디렉터리만 센다.** 부모 아래의 모든 폴더를 이웃으로
세면 작업 사본이 섞여 판정이 흔들린다. 하나도 찾지 못하면 **못 잼**이다 —
전부 내 것이라고 단정하면 남의 것을 지운다.

★ **`~/.ollama/models` 는 자산이다.** 4.5G 지만 지우면 다시 받는다. `doctor`
의 모델 검사가 채택 모델만 남아 있는지 따로 본다.

★ **번역 캐시는 지우지 않는다.** 지우면 재번역이고 과금 엔진에서는 재과금이다
(DECISIONS §5). 위생의 목적은 자리를 비우는 것이지 값을 버리는 것이 아니다.

★ **락을 쥔 것이 이 저장소의 워커일 수 있다.** `run_worker.sh` 가 `uv run` 으로
띄우므로 워커가 살아 있는 동안 락이 잡힌다. 그때는 기다릴 것이 아니라 내리면
된다 — `sweep` 이 둘을 갈라 안내한다(DECISIONS §53).

★ **이웃이 `uv run` 으로 돌고 있으면 캐시 정리가 락에 막힌다.** 결함이 아니라
일시적 충돌이고, 계정 하나에 하나인 캐시이므로 남이 쓰는 중에는 비키는 것이
맞다. `못 잼` 으로 적히고 쥐고 있는 프로세스를 보여준다 — 끝난 뒤 다시 돌린다
(DECISIONS §44).

★ **합계는 실제로 지운 것만 센다.** 캐시는 건수가 아니라 패키지 수라 단위가
다르고, 못 지웠는데 합계에 넣으면 그 수를 보고 한 판단도 틀린다.

★ **패치 판정은 셋이다.** 영수증에 있거나 역적용이 붙으면 `적용됨`, 정방향이
붙으면 `아직 아니다`, 셋 다 아니면 `판정 불가` 다. **역적용 실패는 적용되지
않았다는 증거가 아니다** — 붙은 뒤에 그 파일을 다음 패치가 또 고치면 양쪽 다
안 붙는다(DECISIONS §61).

★ **문법·린트는 세 층이다.** JS 는 `node --check`, 셸은 `bash -n` 과
`shellcheck -S warning`, 파이썬은 `ruff` 의 `F` 규칙이다. 스타일 규칙은 켜지
않는다 — 커밋을 막을 일이 아닌 것을 막으면 급할 때 넘기는 버릇이 든다(§46).

★ **로컬에 린터가 없으면 `SKIP` 이고 CI 에서는 멈춘다.** `doctor` 는 없는 도구를
통과로 세지 않고, CI 는 `doctor` 앞에서 `shellcheck` 와 `uvx ruff` 가 실제로
있는지 먼저 확인한다. 건너뛰면 초록불인 채로 아무도 보지 않는다(DECISIONS §54).

★ **`uv.lock` 을 건드리지 않는다.** `ruff` 를 개발 의존성으로 넣으면 락이 따라
움직여 CI 에서 트리가 더러워진다. `uvx` 로 받아 캐시만 쓴다.

★ **문서에 적은 건수는 파생물이다.** 정본은 실행이고 `doctor` 가 위에서 잰
값을 `tools/check_counts.py` 에 넘겨 대조한다. 문서 쪽은 `<!--count:이름-->`
표시를 단 숫자만 주장으로 센다 — 표시가 없는 숫자는 과거 서술이라 보지 않는다.
재지 못한 이름은 통과가 아니라 `SKIP` 이다(DECISIONS §62).

★ 경로를 박지 않는다. `WIN_DOWNLOADS` 와 `TMPDIR` 을 쓴다.

### 11-8. 모델 관리

벤치에서 진 모델은 즉시 지운다. 필요하면 다시 받는다. `doctor.sh` 가
`.env` 의 `OLLAMA_MODEL` 에 적힌 것 외의 모델을 FAIL 로 보고한다.

★ 모델을 `/mnt/f` 에 두지 않는다. DrvFs 라 2.4GB 로딩에 2분이 걸린다
(DECISIONS §3).

### 11-9. 패치 적용

작업 산출물은 윈도우 다운로드 폴더로 받는다. 경로의 정본은 `.env` 의
`WIN_DOWNLOADS` 이고 스크립트는 그 값을 읽는다.

```bash
bash tools/apply_patch.sh              # 가장 최근 thoth-*.patch
bash tools/apply_patch.sh --check      # 붙는지만 본다
bash tools/apply_patch.sh 이름.patch    # 특정 파일
```

★ **브라우저를 거친 패치는 줄끝이 CRLF 다.** 저장소는 전부 LF 이므로 그대로
적용하면 문맥이 한 줄도 맞지 않아 `patch does not apply` 로 죽는다. 오류
메시지가 내용 불일치처럼 보여 원인을 가리므로 스크립트가 먼저 벗긴다
(DECISIONS §26).

★ **DrvFs 위의 파일을 직접 적용하지 않는다.** 사본을 `/tmp` 에 두고 거기서
줄끝을 정리한다. 원본을 건드리지 않아야 다시 받을 필요가 없다.

★ **역적용이 되면 이미 붙은 패치다.** 스크립트가 이것을 "저장소가 어긋났다"
와 가른다. 둘은 대응이 정반대이므로 같은 오류로 보고하면 안 된다.

★ **적용에 성공하면 영수증을 적는다.** 줄끝을 벗긴 본문의 sha256 이
`.cache/applied-patches.tsv` 에 쌓이고 `sweep` 이 그것을 먼저 본다. 적용하는
순간 아는 것을 버리면 나중에 되알아내야 하고, 붙은 뒤 같은 파일이 또 바뀐
경우는 되알아낼 방법이 없다(DECISIONS §61).

★ 적용 뒤 `.env` 와 `.env.example` 의 키를 비교해 보고한다. 패치는 `.env` 를
담지 못하므로 키가 늘어난 경우 손으로 넣는다.

### 11-10. Lambda 패키지

```bash
bash tools/package_lambda.sh      # dist/worker.zip
```

**의존성이 들어가지 않는다.** `app` 이 모듈 최상위에서 부르는 서드파티가 없고
`boto3` · `botocore` 는 함수 안에서 늦게 불려 Lambda 런타임이 제공한다. 실측
**18KB · 파일 8개**다.

| | |
|---|---|
| 넣는 것 | `app/*.py` · `app/glossary/*.json` |
| 빼는 것 | `main.py`(FastAPI 를 최상위에서 부른다) · `preflight.py`(개발 도구) |

★ **넣지 않는 것과 넣고 안 쓰는 것은 다르다.** `main.py` 를 넣어도 import 되지
않아 무해하지만, 넣어 두면 언젠가 누가 import 한다.

★ **"의존성이 없다" 를 검사로 만든다.** 만든 zip 을 풀어 `fastapi` · `pydantic`
· `starlette` · `uvicorn` import 를 막은 상태에서 핸들러를 실제로 부른다. 말로만
적으면 언젠가 틀린다(DECISIONS §17 · §71).

★ **zip 이 결정적이다.** 타임스탬프를 고정하고 순서를 정렬한다. 그러지 않으면
내용이 같아도 해시가 매번 달라지고, terraform 이 `source_code_hash` 로 그것을
보므로 **고친 것이 없어도 배포가 돈다**(DECISIONS §72).

★ **`zip` · `unzip` 을 부르지 않는다.** 저장소는 이미 `python3` 에 의존하고
`zipfile` 이 표준 라이브러리다. 외부 도구를 하나 더 요구하면 그것이 없는
기계에서 배포가 막힌다.

★ 넣는 것을 목록으로 고른다. `__pycache__` 가 섞이면 런타임이 바이트코드를
쓸지 소스를 쓸지가 조용히 갈린다.

### 11-11. 배포

```bash
bash tools/bootstrap_backend.sh              # 처음 한 번. 상태 버킷을 세운다
bash tools/package_lambda.sh                 # dist/worker.zip 을 먼저 만든다
cp infra/terraform.tfvars.example infra/terraform.tfvars   # worker_token 을 채운다
bash tools/tf.sh init
bash tools/tf.sh apply
WORKER_URL=<출력된 url> WORKER_TOKEN=<토큰> bash tools/smoke.sh
```

★ **terraform 을 직접 부르지 않는다.** `.env` 를 읽지 않으므로 `AWS_PROFILE` 이
비고, 그러면 "No valid credential sources" 가 난다. `tools/tf.sh` 가 로더를 태우고
**자격증명을 CLI 로 풀어 환경변수로 넘긴다** — 프로파일이 SSO 든 `aws login` 이든
정적 키든 terraform 이 그 형식을 몰라도 된다(DECISIONS §74).

| 리소스 | 왜 |
|---|---|
| Lambda (`python3.13`) | zip 배포. 의존성 없음 |
| Function URL (`NONE`) | 확장이 SigV4 를 못 한다. 방어는 토큰(§12) |
| DynamoDB (온디맨드) | 캐시 · 카운터 한 테이블. TTL `expires_at` |
| IAM 역할 | 로그 · 테이블 · `bedrock:InvokeModel` 만 |

★ **zip 을 terraform 이 만들지 않는다.** `package_lambda.sh` 가 "의존성 없이
도는가" 를 함께 확인하므로, 만드는 것과 확인하는 것을 가르면 확인 없이 배포하는
길이 생긴다. 순서가 어긋나면 `filebase64sha256` 이 파일을 못 찾아 `plan` 에서
멈춘다.

★ **크로스리전 추론 프로파일은 IAM 두 자리를 요구한다** — 프로파일 ARN 과 각
리전의 기반 모델 ARN 이다. 프로파일만 허용하면 `AccessDeniedException` 이 나고,
**로컬에서는 되던 것이 Lambda 에서만 안 되므로** 원인을 찾기 어렵다.

★ **`AWS_REGION` 을 환경변수로 넣지 않는다.** Lambda 예약 키라 설정하면 배포가
거부된다. 런타임이 채워 주고 `engine.py` 가 그것을 읽는다.

★ **동시 실행을 고정하지 않는다** — `reserved_concurrency` 기본값이 `-1` 이다.
신규 계정은 총 동시성이 10 이라 예약하면 미예약분이 최소값 아래로 떨어진다.
**계정 전체가 10 이므로 예약 없이도 천장이 있고**, 한도를 올리는 순간 그 천장이
사라지므로 그때 이 값을 함께 올린다(DECISIONS §75).

★ **`tools/tf.sh` 의 안내는 `stderr` 로 나간다.** `$(bash tools/tf.sh output -raw
worker_url)` 이 안내 줄까지 삼켜 URL 이 오염된 적이 있다. 사람에게 하는 말과
도구가 읽는 값은 통로를 나눈다.

★ **상태는 로컬에 둔다.** 리소스가 넷이고 전부 재생성 가능하며 유휴 비용이 0
이라, 상태를 잃어도 고아 리소스가 돈을 태우지 않는다. `*.tfstate` 와 `*.tfvars`
는 `.gitignore` 가 막는다.

★ **`doctor` 가 `fmt` 를 항상 보고 `validate` 는 `infra/.terraform` 이 있을 때만
본다.** `validate` 는 `init` 을 요구하고 `init` 은 프로바이더를 받는다. 커밋마다
받게 하면 검사가 네트워크에 기댄다(DECISIONS §73).

### 11-12. 엔진 전제

```bash
bash tools/preflight.sh                  # 현재 엔진
ENGINE=bedrock bash tools/preflight.sh   # 이번 한 번만 다른 엔진으로
bash tools/bedrock_survey.sh             # Bedrock 쪽 실정을 잰다
```

엔진마다 기동 전제가 다르다. `local` 은 ollama 응답, `bedrock` 과 `translate`
는 자격증명과 실제 호출, `echo` 는 아무것도 아니다. 정본은
`worker/app/preflight.py` 의 `CHECKS` 레지스트리이고 `run_worker.sh` 와
`doctor.sh` 는 결과를 옮겨 적는다.

★ **호출부가 엔진 이름을 묻지 않는다.** 엔진마다 `if` 를 붙이면 그 엔진의
기본값도 호출부가 갖게 되고, 실제로 `OLLAMA_URL` 기본값이 세 곳에 있었다
(DECISIONS §58).

★ **재인증 명령은 프로파일이 정한다.** `sso_session` · `sso_start_url` 이면
`aws sso login`, `login_session` 이면 `aws login` 이다. 둘 다 아니면 아무
명령도 내지 않는다 — 틀린 원인을 단정하는 메시지는 침묵보다 나쁘다(§37).

★ **`preflight` 와 `bedrock_survey` 는 역할이 다르다.** 전자는 "지금 돌릴 수
있는가" 에 예/아니오로 답하고, 후자는 아니오일 때 무엇이 있는지 본다. 모델
접근 승인 자체는 콘솔에만 있다.

### 11-13. 토큰 실측

```bash
CACHE_FILE=/tmp/bench-cache-3.json ENGINE=bedrock bash tools/run_worker.sh > /tmp/w3.log 2>&1 &
python3 tools/bench_golden.py --batch 3 --json /tmp/b3.json
python3 tools/usage_report.py --drop-warmup /tmp/w3.log
```

`bedrock` 엔진이 호출마다 `usage` 한 줄을 남긴다 — 배치 크기 · 본문 문자 ·
프롬프트 머리 문자 · 입력 토큰 · 출력 토큰 · 지연. `usage_report.py` 가 그것을
배치 크기별로 모은다.

★ **문자와 토큰을 한 표에 놓는다.** `chars_used` 는 원문만 세고 과금은 입력
토큰으로 매겨져 두 수가 7배 갈린다(§7-0-1). 하나만 보면 다른 하나를 짐작하게
된다.

★ **판마다 캐시 파일을 딴 데로 보낸다.** 히트한 문장은 호출하지 않으므로
`usage` 줄도 남지 않는다. 지우지 않고 옮기는 이유는 §11-4 와 같다 — 지우면
번역이 버려지고 과금 엔진에서는 재과금이다.

★ **판마다 워커를 다시 띄운다.** 캐시 파일을 갈아도 앞 판의 워커가 메모리에
들고 있다(DECISIONS §50).

★ **단가를 곱하지 않는다.** 이 도구는 토큰까지만 센다. 정본은 결제 콘솔이고
기억으로 적은 단가는 늙는 숫자다(DECISIONS §62).

★ **웜업도 로그에 남는다.** 러너가 집계 밖에 두는 그 호출도 Bedrock 을
때린다. `--drop-warmup` 이 첫 줄을 빼고 뺐다는 사실을 적는다. 자동으로 빼지
않는다 — 프로덕션 로그에는 웜업이 없고, 무엇이 빠졌는지 모르는 집계가 가장
위험하다.

★ **`n=1` 행은 개별 폴백이다.** 배치 파싱이 깨진 자리이며 과금 엔진에서는
호출 수가 그대로 돈이다. 도구가 따로 알린다.

★ **`local` 은 이 줄을 남기지 않는다.** 과금이 0 이라 잴 이유가 없다.

★ **로그는 stdout 으로 나간다.** 배선은 `worker/app/__init__.py` 에 있고 두
진입점이 같은 것을 쓴다. 배포본에서는 Lambda 가 stdout 을 CloudWatch 로 담으므로
같은 줄을 Logs Insights 로 모은다.

### 11-14. 배포본 드리프트

```bash
bash tools/package_lambda.sh
python3 tools/deploy_drift.py
```

Lambda 가 들고 있는 `CodeSha256` 과 방금 만든 zip 의 해시를 비교한다. zip 이
결정적이라(§11-10) 두 수가 같으면 배포본이 이 커밋의 코드다.

★ **CI 가 이것을 돌린다**(`.github/workflows/drift.yml`). 푸시마다 한 번, 하루에
한 번. **드리프트는 커밋이 아니라 시간이 만든다.**

★ **`doctor` 는 부르지 않는다.** 로컬에서는 네트워크 · 자격증명 · zip 유무가
제각각이라 "못 쟀다" 가 기본값이 되고, 기본값이 된 경고는 읽히지 않는다
(DECISIONS §86).

★ **못 재면 실패다.** CI 에서는 전제가 항상 참이므로 못 잰 것은 고칠 일이지
넘어갈 일이 아니다. 종료 코드는 0 같다 · 1 못 쟀다 · 2 다르다.

★ **해시는 base64 다.** `sha256sum` 의 16진수와 비교하면 영원히 다르다.

### 11-15. 원격이 거절하는 것

```bash
python3 tools/check_static.py
```

`doctor` 가 부른다. 둘을 본다.

| | |
|---|---|
| `.github/workflows/*.yml` | YAML 로 파싱되는가 |
| `infra/*.tf` 의 `resource` 블록 | 인용 문자열이 ASCII 인가 |
| `.github/workflows/*.yml` 의 `uses:` | 아는 Node 20 메이저로 되돌아가지 않았는가 |

★ **문법은 맞는데 받는 쪽이 거절하는 것들이다.** `terraform validate` 는 HCL 을
보지 AWS API 의 값 제약을 보지 않고, git 은 YAML 을 보지 않는다. 그래서 둘 다
원격에 나간 다음에야 안다.

★ **깨진 워크플로는 조용히 사라진다.** `gh workflow run` 이 "could not find any
workflows named ..." 를 내는데, 그 문구는 파일이 아예 없을 때와 같다.

★ **`resource` 블록 안만 본다.** `variable` · `output` 의 설명은 terraform 안에서
끝난다. 거기까지 막으면 한글 문서를 쓰지 말라는 말이 된다.

★ **액션 메이저**(2026-09-16). `checkout@v5` · `setup-python@v6` · `setup-node@v5`
· `setup-uv@v7` · `setup-terraform@v4` · `configure-aws-credentials@v6` 가 Node 24 다.
`gitleaks-action@v2` 는 확인하지 못해 목록에 없다(DECISIONS §100).

★ **`yaml` 이 없으면 `SKIP` 이다.** 린터 취급과 같고 CI 가 그것을 따로 막는다
(DECISIONS §54).

### 11-16. 상태 백엔드

상태는 S3 에 있다. `bash tools/bootstrap_backend.sh` 가 버킷을 세우고
`infra/backend.hcl` 을 만든다. 처음 한 번만 하는 일이다.

★ **버킷 이름이 저장소에 없다.** 부분 설정이고 `backend.hcl` 은 gitignore 다.
이름에 계정 ID 가 들어가는데 비밀은 아니나 공개 저장소 앞문에 걸 값도 아니다.

★ **이 버킷만 terraform 이 소유하지 않는다.** 상태를 담는 것을 상태로 관리하면
지울 때 자기 발을 딛는다. 대신 스크립트가 버전 관리 · 퍼블릭 차단 · 기본 암호화를
매번 다시 건다 — **손으로 만들면 그 셋을 잊는다.**

★ **잠금은 S3 가 한다**(`use_lockfile`). DynamoDB 테이블을 세우지 않는다.

★ `tools/tf.sh` 가 `init` 에만 `-backend-config` 를 붙인다. 나머지 명령은
`.terraform/` 에 적힌 것을 읽는다.

★ **이전 뒤 `plan` 이 `No changes` 여야 한다.** 아니면 상태가 옮겨지지 않았고,
그 상태로 `apply` 하면 **이미 있는 리소스를 다시 만든다.**

### 11-17. 태그 배포

```bash
git tag v0.1.0 && git push --tags
```

`production` Environment 의 승인을 거쳐 `terraform apply` 가 돈다. 끝나면
드리프트 검사가 같은 워크플로 안에서 배포본을 확인한다.

★ **승인이 곧 자격증명의 조건이다.** 배포 역할은 `sub` 가
`...:environment:production` 인 토큰만 받고, 그 `sub` 는 Environment 를 거쳐야
발급된다.

★ **Environment 는 이름만으로 승인을 요구하지 않는다.** 보호 규칙이 있어야
멈춘다. 지금 규칙은 둘이다 — required reviewers(`CleverAIFox`, 셀프 승인 허용)와
배포 대상 제한(`v*` 태그만). 2026-09-16 까지는 둘 다 없었고 `v0.1.0`~`v0.1.3` 이
승인 없이 돌았다(DECISIONS §98).

```bash
gh api repos/CleverAIFox/thoth/environments/production \
  --jq '{rules: [.protection_rules[].type], branch: .deployment_branch_policy}'
```

★ 대기 중인 run 은 CLI 로도 승인된다.

```bash
RUN=<run id>
ENV_ID=$(gh api repos/CleverAIFox/thoth/actions/runs/$RUN/pending_deployments --jq '.[0].environment.id')
gh api -X POST repos/CleverAIFox/thoth/actions/runs/$RUN/pending_deployments \
  -F "environment_ids[]=$ENV_ID" -f state=approved -f comment="<사유>"
```

★ **IAM 변경은 CI 에서 멈춘다.** 배포 역할에 IAM 쓰기가 없다. `AccessDenied` 가
나면 그 변경은 손으로 `apply` 하라는 뜻이다 — **결함이 아니라 경계다**
(DECISIONS §89).

★ 필요한 시크릿 셋 — `AWS_DEPLOY_ROLE_ARN` · `AWS_STATE_BUCKET` ·
`WORKER_TOKEN`. 앞의 둘은 `tf.sh output` 과 `infra/backend.hcl` 에 있다.

★ **쓰기 경로가 지나갔다.** `v0.1.3` 이 `lambda:UpdateFunctionCode` 를 처음으로
통과시켰다(CloudTrail `GitHubActions` 2026-09-16 11:46:40 UTC). 같은 `apply` 에서
새 콜드패스 리소스 생성은 전부 거절됐다 — **terraform 은 병렬로 돌므로 한
`apply` 안에서 성공과 거절이 섞인다**(DECISIONS §98).

★ **IAM 이 섞인 변경은 손 `apply` 가 먼저다.** 태그를 먼저 밀면 코드는 올라가고
나머지는 반쯤 멈춘다. 순서는 손 `plan -out` → 손 `apply` → 태그다.

★ **정책이 프로바이더 버전에 묶여 있다.** refresh 가 부르는 읽기 액션은
`aws` 프로바이더가 정한다. `~> 6.0` 을 올릴 때 배포 역할을 함께 본다.

### 11-18. 콜드패스 — 쌍 로그

캐시 미스 한 건이 stdout 에 JSON 한 줄로 나가고 `infra/analytics.tf` 가 그것을
S3 Parquet 로 옮긴다. **자체 번역 모델의 학습 데이터가 쌓이는 자리다**
(DECISIONS §97).

```
Lambda stdout ─ 로그 그룹 ─ 구독 필터 { $.k = "pair" }
  ─ Firehose (GZIP 해제 · 메시지 추출 · JSON→Parquet)
  ─ s3://thoth-pairs-<계정>/pairs/dt=YYYY-MM-DD/
  ─ Glue thoth.pairs (파티션 투영) ─ Athena
```

| 열 | 뜻 |
|---|---|
| `k` · `v` | 판별자 `pair` · 스키마 버전 |
| `ts` · `h` | 에포크 ms · `sha256(src)` — 캐시 키와 같다 |
| `src` · `raw` · `ko` | 원문 · **모델 출력** · 후처리 결과 |
| `engine` · `model` · `prompt` | 조건. `prompt` 는 골든셋 기준선과 같은 지문이다(배치 제외) |
| `book` · `n` | 고른 용어집 · 한 번에 번역한 미스 수 |
| `site` · `adapter` | 확장이 보낸 호스트와 어댑터. 옛 클라이언트는 null |
| `ver` | 워커 계약 버전 |

★ **줄 전체가 JSON 이다.** `thoth.pair` 로거가 접두사 없이 쓴다. 접두사가
붙으면 Parquet 변환이 전부 `errors/` 로 간다.

★ **캐시 히트는 적지 않는다.** 같은 원문의 쌍은 처음 번역될 때 한 번이다.

★ **검사 축을 쓸 때 돌리지 않는다.** 위반 판정은 읽을 때 `bench_golden.py` 의
함수로 한다. 축이 늘면 옛 데이터에도 새 자를 댈 수 있다.

★ **쌍은 학습용이다.** 원문은 사이트의 저작물이고 저장소는 공개다. 버킷도
데이터셋도 공개하지 않는다.

★ **첫 `apply` 는 손으로 한다.** 이 파일이 IAM 역할 둘을 만들고 배포 역할에는
IAM 쓰기가 없다(§11-17). 그 뒤 태그 배포는 콜드패스를 읽기만 한다.

★ **배포 역할은 콜드패스를 읽기만 한다.** `v0.1.3` 재실행에서 refresh · plan ·
apply 가 `0 changed` 로 통과했다(2026-09-16). **쓰기는 없다** — 수명주기 규칙
하나를 바꿔도 CI 가 아니라 손으로 `apply` 한다.

★ **계정은 유료 플랜이다.** Free 플랜에서는 Firehose 생성이
`SubscriptionRequiredException` 으로 막혔고, 플랜이 끝나면 계정이 닫혀 버킷도
사라진다. 크레딧은 유료 전환 뒤에도 남는다. 예산 알림 `thoth-5usd` 가 월 $4 에서
메일을 보낸다(DECISIONS §98).

★ **구독 필터를 만들면 `errors/` 에 한 건이 생긴다.** CloudWatch Logs 의 제어
메시지가 메시지 추출 뒤 빈 레코드가 되어 변환에 실패한 것이다(`rawData` 가
비어 있다). `pairs_check.sh` 는 그것을 따로 센다.

★ **Athena 결과는 같은 버킷 `athena/` 에 떨어지고 7일 뒤 지워진다.**

★ **`destroy` 는 쌍 버킷에서 멈춘다.** `force_destroy` 가 꺼져 있다. 다시 만들 수
없는 데이터라 의도한 동작이다.

확인은 로그가 아니라 버킷과 테이블을 본다.

```bash
bash tools/pairs_check.sh            # 오늘(UTC)
bash tools/pairs_check.sh 2026-09-16
```

| 종료 코드 | 뜻 |
|---|---|
| 0 | 쌍이 있고 Athena 가 읽는다 · 쌍이 든 오류 없음 |
| 1 | 쌍이 든 변환 오류 · 못 읽은 오류 객체 · Athena 실패 |
| 3 | 그날 쌍이 없다 — 못 잼 |

★ **오류 객체는 `tools/pairs_errors.py` 가 가른다.** 제어 메시지 · 쌍이 든 오류 ·
못 읽음 셋이다. jq 를 쓰지 않는다(DECISIONS §99).

★ **첫 실측**(2026-09-16). probe 한 건이 12:56 UTC 배치로 Parquet 3,440바이트가
됐고 Athena 가 `bedrock · apac.amazon.nova-lite-v1:0 · probe.local · curl · n=1`
로 읽었다.

## 12. 접근 토큰

`WORKER_TOKEN` 이 비면 워커가 열린다. 채우면 `X-Thoth-Token` 헤더를 요구하고
불일치하면 401 이다. 확장은 `chrome.storage.local` 의 `stToken` 에서 읽어
같은 헤더에 싣는다.

| 설정 | `/translate` | `/health` |
|---|---|---|
| 토큰 없음 | 열림 | 전부 응답 |
| 토큰 있음 · 헤더 맞음 | 통과 | 전부 응답 |
| 토큰 있음 · 헤더 없음·틀림 | 401 | 기동 정보만. 잔여 문자는 빠진다 |

★ **월 상한은 비용을 막지 남용을 막지 않는다.** 지출은 상한에서 멈추지만
그 상한을 누가 태우는지는 상한이 정하지 않는다. 남이 태우면 지출은 0 원 늘지
않은 채 정당한 사용자가 429 를 받는다(DECISIONS §25).

★ **확장에 심는 토큰은 비밀이 아니다.** 사용자가 꺼내볼 수 있으므로 작정한
공격자를 막지 못한다. 막는 대상은 엔드포인트를 주운 사람이고, 그것이 실제
위험의 대부분이다. 완전하지 않다는 이유로 아무것도 두지 않는 쪽이 더 나쁘다.

★ **비교는 `secrets.compare_digest` 로 한다.** 문자열 `==` 는 앞에서부터
끊어 길이와 접두사가 새어 나간다.

★ **401 도 CORS 헤더를 달고 나간다.** 인증 실패가 브라우저 콘솔에 CORS 위반으로
보이면 원인을 찾지 못한다(DECISIONS §2).

★ **`/health` 는 토큰 없이도 답한다.** 기동 여부를 묻는 데 비밀이 필요하면
헬스체크가 비밀을 들고 다닌다. 다만 `chars_used` · `chars_remaining` 은 인증된
호출에만 실린다 — 남의 상한이 얼마나 닳았는지는 공개할 정보가 아니다.

★ `doctor.sh` 가 원격 설정(`ENGINE=bedrock|translate` 또는 `CACHE=ddb`)에서
토큰이 비면 FAIL 한다. 로컬 전용 설정에서는 OK 로 가른다. 검사 대상을
뭉뚱그리면 맞는 상태를 위반으로 잡는다(DECISIONS §22).

★ 토큰이 없을 때 확장은 헤더를 아예 붙이지 않는다. 빈 값으로 보내면 단순
요청이 아니게 되어 preflight 가 도는데, 얻는 것 없이 왕복만 는다.
